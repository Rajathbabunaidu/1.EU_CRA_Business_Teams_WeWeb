# EU CRA Hub — Business Teams (WeWeb coded element)

## What this is
A Vue 3 **WeWeb coded element** intended to be placed inside your existing **Settings / Security / Administration / Business Teams** page. It does **not** contain or replace the app's existing red sidebar or other routes. Import this repo as an **Element**, not a Section or Plugin.

### Included
- Right-hand WeWeb settings for **Supabase Project URL** and **Supabase Publishable Key** (entered in WeWeb, never in GitHub).
- Live team data, Active / Inactive / Archived labels, Total / Active / Inactive KPIs (optional total memberships).
- Create / Edit / View team; no hard-delete action. Team codes remain generated by Supabase and are never editable.
- Read-only member list including name, code, email, job title, and user status.
- Search, status filter, ascending/descending sorting, pagination (10 / 25 / 50 / 100).
- Table Columns dialog: show/hide and reorder standard columns and active custom fields.
- Column layout stored **per browser** using `localStorage` until authenticated user-specific storage is available.
- Manage Fields dialog: can display/create/deactivate field definitions **only when database permissions permit**. Add/Edit Team supports field values where accessible.
- Error handling: restricted custom-field tables do not break basic Teams UI.

## 1. GitHub
1. Extract the ZIP.
2. Create a new GitHub repository, for example `eu-cra-business-teams-weweb`.
3. Place the **contents of this extracted folder** at the repository root (so `ww-config.js`, `package.json`, `src/wwElement.vue` are at the expected paths).
4. Run:

```bash
git init
git add .
git commit -m "Initial Business Teams WeWeb coded element"
git branch -M main
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPO.git
git push -u origin main
```

## 2. WeWeb
1. Go to **Development → Coded components → Elements**, import the GitHub repository.
2. Select the `main` branch and activate the successful build/version.
3. In **Add Element → Your project → Coded components**, drag **EU CRA Hub — Business Teams** into the existing page content area.
4. Select the **coded element itself** (not its parent container) and open its right-side settings.
5. Set **Supabase Project URL** to `https://YOUR-PROJECT-REF.supabase.co` (no `/rest/v1`).
6. Set **Supabase Publishable Key** to `sb_publishable_...`.
7. Choose editing and table options. Click **Refresh**. Confirm live teams and member counts.

**No URLs or keys are hardcoded in source. Never paste a service-role or `sb_secret_...` key into WeWeb.**

## 3. Backend compatibility

Uses existing tables exactly as verified:
- `public.teams(id, team_code, team_name, description, status_id, created_at, updated_at)`
- `public.team_memberships(id, team_id, user_id, created_at)`
- `public.user_profiles(id, user_code, full_name, email, job_title, status_id)`
- `public.user_statuses(id, status_name)`
- Optional `public.cra_custom_field_definitions`, `public.cra_custom_field_values`.

The component uses the Supabase Data REST API with the **`apikey` header only for publishable keys**. A legacy JWT anon key (if used) is additionally sent on the Authorization header for compatibility. It performs no external script imports or requests to third-party services.

### Access limitations in your current database
The existing Teams, membership, user and status tables allow `anon` access. The three CRA custom-field / preference tables currently have RLS **enabled** and `anon` privileges **revoked**. Therefore:
- Basic Teams works using the publishable key (assuming URL, API availability and network access).
- **Custom field definition/value features are unavailable until the backend provides authorized access.** The UI will show a non-blocking notice. Do not grant unrestricted anonymous writes to enable these features.
- User-specific `cra_table_view_preferences` persistence is **not** enabled while the app lacks user identity and authorized access. Browser-local column preferences are available instead.

### Safety and integrity
- The frontend does **not** provide team deletion or member-assignment editing.
- Creating/updating a team and then saving custom-field values are multiple REST calls, **not an atomic database transaction**. If a custom-field save fails after the team save, the dialog reports partial success so the user can retry safely.
- Supabase publishable keys are public identifiers, **not access control**. Existing anonymous INSERT/UPDATE permissions on business tables are not safe for public production deployment. Protect the environment and implement proper authorization before publishing publicly.

## 4. Troubleshooting
- **Configuration needed**: select the element, add URL/key in its settings.
- **Failed to fetch**: incorrect URL, blocked network, project paused, browser CORS, or browser connectivity.
- **HTTP 401/403 on core data**: bad key, missing grants, or policies.
- **Custom fields unavailable**: expected while CRA custom-field tables restrict anonymous access.
- **Empty counts**: inspect whether `team_memberships` can be read.
- **Updated code not visible**: bump `package.json` version, push, then activate the new GitHub build in WeWeb.

This package has been statically checked but has not been connected to your live Supabase project or imported into your WeWeb workspace from this environment.
